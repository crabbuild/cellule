Cellule is an embedded framework. Your application declares modules and Cell topology; the framework handles fenced ownership, durable request outcomes, and verified recovery. Your service owns HTTP ingress, authorization, credentials, and deployment.

## Start with a working application

Run the [local quickstart](/docs/guides/quickstart) to exercise all eight primitives with temporary SQLite files and in-memory storage. It requires Rust 1.97 or newer and no cloud credentials.

```sh
cargo run -p cellule-app --example sql --locked
```

The SQL example commits order 42, reads it at the returned receipt, checks its total, and drains the runtime. Open the [complete runnable source](https://github.com/crabbuild/cellule/blob/main/crates/cellule-app/examples/sql.rs) while following the guide.

## The contracts to keep

- A Cell has one fenced writer. A successful command follows durable publication or recoverable follower-log proof.
- A command changes one Cell. Cross-Cell work uses durable Effects and an idempotent destination inbox.
- Recovery verifies the authority-pinned root and every required chunk. State is reconstructed byte-identically or recovery fails.
- A receipt binds a later read to a position in the same Cell.
- Shutdown drains accepted work and releases resources on every exit path.
