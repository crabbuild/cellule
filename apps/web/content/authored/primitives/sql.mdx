A parameterized batch changes one Cell. Queries can require its committed receipt.

<PrimitiveDiagram id="sql" />

## Use the typed capability

Obtain `sql::<M>(target)` from an `ApplicationHandle` bound to the tenant and application. Its entry points are **batch, query**. The compiled module and Cell type determine the role and partition rules.

| Contract          | Behavior                                                                 |
| ----------------- | ------------------------------------------------------------------------ |
| Ownership         | One fenced writer per Cell.                                              |
| Mutation identity | Keep the same request ID when resolving or retrying one logical command. |
| Response          | Success follows durable publication or recoverable follower proof.       |
| Read consistency  | A receipt constrains a read in the same Cell.                            |
| Recovery          | State and recorded outcomes restore together.                            |

## Run the example

```sh
cargo run -p cellule-app --example sql --locked
```

The [complete runnable source](https://github.com/crabbuild/cellule/blob/main/crates/cellule-app/examples/sql.rs) includes module registration, provisioning, invocation, and shutdown. Examples use temporary SQLite and in-memory object storage.
